# ТЗ: двигун Earth Jukebox v2 — «спершу зрозуміти все відео, потім писати музику»

Це розширення плану `docs/plan-v2.md` (структура src/, формати між шарами лишаються).
Мета: вже перша версія має бути потужною — аналізувати КОЖЕН кадр, але розуміти
ВСЕ відео цілком, адаптуватися до масштабу змін і звучати як живий ансамбль
(струнні, фортепіано, арфа, духові), а не як окремі ноти синтезатора.

Головний принцип: **музика пишеться тільки після того, як двигун «подивився» все відео
й зрозумів, що в ньому відбувається, наскільки великі зміни і де головні події.**
Як композитор, який спершу переглядає весь фільм, а потім пише саундтрек.

---

## 0. Загальні правила
- Не ламати `prototype/` — це запасне демо.
- Комітити після кожного етапу (див. розділ 9) — завжди мати робочу версію.
- Детермінованість: однаковий файл → однакова музика (seeded RNG).
- Чесність: двигун ніколи не робить «драму з шуму». Якщо зміни менші за шум — так і кажемо.
- Кожне рішення пояснюване (`explain`) і доступне скрінрідеру.
- Інтерфейс і тексти — українською, код — англійською.

## 1. Двопрохідний аналіз відео

### Прохід A — «огляд» (швидкий, ~1–2 с)
Рівномірно взяти 32 кадри по всьому відео (зменшені до ~160×80) і побудувати **профіль відео**:

1. **Статична маска.** Для кожного пікселя — дисперсія яскравості/кольору між 32 кадрами.
   Пікселі, що майже не змінюються весь час, = статика: суша, фон, підписи, легенда, логотипи,
   рамки. Їх виключаємо з аналізу динаміки (але суша/фон лишається як «тиша/пауза» в мелодії).
   Окремо: сірі пікселі низької насиченості = суша; дуже темні = фон.
2. **Тип сцени** (класифікатор на простих правилах, з упевненістю 0..1):
   - `heatmap` — багато насичених кольорів, градієнт синій→червоний (як ECCO2);
   - `nightlights` — переважно темний кадр (median V < 0.15), рідкі яскраві точки, низька насиченість;
   - `truecolor` — супутникові «справжні кольори» (хмари білі, суходіл зелено-бурий, океан темно-синій);
   - `chart` — багато однотонного фону, тонкі лінії, текст, осі;
   - `mixed` — інакше.
   Тип можна перевизначити в `samples/catalog.json`.
3. **Діапазони кожної ознаки по всьому відео:** p2, p5, p50, p95, p98, середнє, std.
4. **Рівень шуму (noise floor):** медіана різниці між сусідніми кадрами в «спокійних» зонах
   + шум стиснення відео. Усе, що нижче ~2× шуму, вважається «змін немає».
5. **Масштаб змін:** відношення (p95 − p5) реальних змін до шуму → `changeScale`
   (`tiny` / `small` / `moderate` / `large`). Для темного нічного відео з ледь помітними
   змінами це буде `tiny` — і двигун має це врахувати (див. розділ 2).
6. **Межі сцен і службові кадри:** різкі стрибки між кадрами (склейки, титри, чорні кадри,
   початок циклу відео) → межі розділів або кадри, які ігноруємо.
7. **Періодичність:** автокореляція середнього значення → чи є сезонний цикл / петля
   (океанські відео часто показують сезони). Це потім стане повторюваним мотивом у музиці.

Результат: `videoProfile = { sceneType, confidence, staticMask, landMask, ranges, noiseFloor,
changeScale, cuts, period, durationSec }`.

### Прохід B — «детальний» (кожен кадр)
- Частота семплювання адаптивна: мета 300–800 кадрів аналізу на відео, мінімум 4 кадри/с,
  максимум — реальний fps відео. Для коротких відео — кожен кадр.
- Роздільність аналізу ~270×135 (або пропорційно до відео), один прохід пікселів на кадр
  (`frame-context.js`): h, s, v, luma + маски з проходу A.
- Обробка пікселів — у Web Worker (передаємо ImageData як transferable), щоб UI не зависав.
  Прогрес-бар + aria-live «Аналізую кадр 120 з 640».
- **Кеш:** результат аналізу зберігати в IndexedDB (ключ: ім'я+розмір+тривалість файлу).
  Для відео з галереї — заздалегідь зберегти `samples/<id>.analysis.json`,
  щоб демо для журі стартувало миттєво й надійно.

## 2. Адаптація до масштабу (щоб і темне відео з малими змінами звучало виразно — але чесно)

Для кожної ознаки зберігаємо **два канали**:
- `abs` — абсолютне значення 0..1 у фізичній шкалі (наприклад, тепло за кольором легенди).
  Відповідає на питання «наскільки тут тепло/яскраво взагалі».
- `rel` — відносне значення в межах цього відео, нормоване робастно за p5..p95.
  Відповідає на питання «це багато чи мало для ЦЬОГО відео».

Правила нормалізації:
- Робастна нормалізація за перцентилями (не min/max — один шумний кадр не має ламати шкалу).
- Для ознак з «довгим хвостом» (яскравість нічних вогнів, кількість точок) — логарифмічна
  або гамма-шкала: `log(1 + k·x)`; тип шкали обирається автоматично за асиметрією розподілу.
- **Поріг значущості:** зміна, менша за `noiseFloor`, у `rel` не підсилюється (м'яке
  коліно, а не обрізання), щоб шум не перетворювався на драму.
- **Коефіцієнт підсилення** `gain = 1 / (p95 − p5)` фіксується й показується:
  «Зміни в цьому відео малі (±2.5 %), тому їх підсилено ×8». Це в UI, в explain і для скрінрідера.
- Мапінг (шар 2) сам вирішує, що брати: `abs` (загальний настрій, лад) чи `rel` (рух, напруга).
  За замовчуванням: настрій/лад ← abs, динаміка/ритм/мелодія ← rel.

Так темне нічне відео отримає тиху, темну за настроєм музику (abs), але виразний рух
усередині неї (rel), а журі й слухач чують чесне пояснення масштабу.

## 3. Ознаки (шар 1) — що рахувати на кожному кадрі

### Базові (всі типи сцен)
warmth (тепловий індекс за hue або за легендою), saturation, brightness (luma), contrast (std luma),
activeMass (частка «даних» поза статикою/фоном), landShare, centerY (вертикальний центр мас
активності), balanceLR (захід/схід), outliers3σ (кількість і позиції викидів), frameDiff
(зміна відносно попереднього кадру, тільки по динамічних пікселях), colorClusters (K-Means на
малій сітці, k ≤ 8), edgeDensity (Собель), entropy (гістограма luma).

### Залежні від типу сцени
- `heatmap`: значення за кольоровою шкалою (hue-рампа або точки легенди з catalog.json → реальні
  одиниці, напр. °C), частка «гарячих» і «холодних» зон, середнє по широтних поясах.
- `nightlights`: luma у лог-шкалі, кількість світлових точок (поріг відносно фону), кількість і
  розмір кластерів (зв'язні області), «щільність агломерацій», частка темряви.
- `truecolor`: білизна (хмари/лід), «зеленість» (рослинність), темно-синє (вода).
- `chart` — поки тільки базові; повноцінне зчитування ліній графіка — окрема задача пізніше.

### Просторові масштаби (для кожної скалярної ознаки, де це має сенс)
- весь кадр;
- сітка 16 колонок × 8 рядків (колонки = кроки сканування для мелодії);
- широтні пояси: полярний Пн, помірний Пн, тропіки, помірний Пд, полярний Пд;
- півкулі захід/схід;
- **гарячі точки:** top-3 регіони з найбільшою зміною за відео — відстежувати їх у часі
  (це «солісти» оркестру).

### Часові масштаби (temporal.js, для кожної скалярної ознаки)
`.d1` (зміна за кадр), `.speed10`, `.accel20`, `.trend40`, `.pos` (позиція в усьому відео 0..1),
`.globalRank` (наскільки це значення екстремальне серед усього відео).

### Події (детектор над усім відео — можливий, бо аналіз зроблено наперед)
peak / trough (локальні екстремуми зі значущістю вище шуму), thresholdCross (перетин p90/p10),
changePoint (точки зміни режиму — простий CUSUM або порівняння середніх у вікнах),
globalMax / globalMin (кульмінація всього відео), returnOfState (стан, схожий на вже бачений —
для повернення музичного мотиву).

  Обирається за `videoProfile.sceneType`, можна перевизначити в catalog.json.

## 5. Композитор (шар 3) — жива музика, а не окремі ноти

### Форма всього треку (бачимо все відео наперед)
- Розділи з кривої energy + changePoints: Вступ → Наростання → Кульмінація (на globalMax
  значущості) → Розв'язка. Довжина розділів кратна 4 тактам.
- Перед зміною розділу — перехід: тарілка-свел, крещендо струнних, затримка гармонії.
- Якщо знайдено періодичність (сезони) — головний мотив повертається на кожному циклі
  з варіацією (інша оркестровка/гармонізація). `returnOfState` → повернення мотиву.

### Гармонія
- Лад з brightness/abs-тепла: лідійський → мажор → міксолідійський → дорійський → мінор → фригійський.
- Банк прогресій під рівні tension (спокійні I–V–vi–IV / i–VI–III–VII, напружені з b2, тритоном,
  зменшеними акордами); зміна акорду раз на 1–2 такти.
- Голосоведення: між акордами мінімальний рух голосів (не стрибати всіма нотами одночасно).
- Розширення акордів за tension: тризвук → 7 → add9 / sus → кластери b2 / тритон на піку.

### Партії (оркестр) — ролі прив'язані до даних
- **Бас (контрабас / віолончель pizz.)** — полярні пояси й загальний рівень; тоніка/квінта, рух за трендом.
- **Педи (струнна група legato, тихо)** — гармонічна «підкладка», гучність = activeMass.
- **Фортепіано / арфа (арпеджіо)** — помірні широти; дрібність (четверті → восьмі → шістнадцяті)
  = density / швидкість змін.
- **Головна мелодія (скрипка або флейта)** — тропіки / гарячі точки; фрази по 2–4 такти з contour,
  мотив + повтор + варіація, каданс у кінці фрази; legato для плавних змін, staccato для різких.
- **Контрмелодія (віолончель / валторна)** — відповідає мелодії (питання–відповідь), вступає з
  наростанням.
- **Ударні (литаври, м'яка перкусія, шейкер)** — ритм за density; литаври на піках і переходах.
- **Акценти / події** — дзвони, челеста, брас-стаби на peak / thresholdCross / outliers3σ.
- **Для nightlights** — окрема оркестровка: челеста, глокеншпіль, арфа, «зоряний дощ» коротких
  нот за кількістю вогнів; темні зони = глибокий дрон з довгою реверберацією.
- Скільки партій звучить одночасно — за orchestration/energy (вступ — 2 партії, кульмінація — всі).

### Виконання
- Humanize: тайминг ±10–20 мс, сила удару ±10 %, легкий свінг для арпеджіо (seeded).
- Динаміка: крещендо/діминуендо за energy; панорама за довготою (захід — ліворуч, схід — праворуч).
- Простір: Tone.Reverb (більше «повітря» для холодних/темних сцен), легкий дилей для мелодії.
- Мастер: компресор + лімітер.

## 9. Порядок роботи (комітити після кожного етапу)
1. Прохід A + videoProfile + картка «що зрозумів» (без музики) → перевірити на ecco2 і синтетичному темному відео.
2. Прохід B у Worker + адаптивна нормалізація abs/rel + temporal + події + кеш.
3. Мапінг-пресети + mapper з explain.
4. Композитор: форма + гармонія + бас/педи/арпеджіо/ударні на PolySynth → **вже звучить**.
5. Мелодія фразами + контрмелодія + акценти подій.
6. Семпли (Sampler) із запасом на синтезатори.
7. UI: таймлайн, таблиця мапінгу, mute/solo, a11y.
8. `samples/*.analysis.json` для галереї, друге відео в галерею.
Після кожного етапу коротко звітуй: що зроблено, як перевірено, що далі.
Якщо щось із цього ТЗ не встигаємо до дедлайну — скажи, що саме пропонуєш спростити.
