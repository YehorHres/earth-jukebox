# PROMPT v3 — тема, область даних, бібліотека звуків, режим дослідження

Розширює plan-v2 і PROMPT-v2-engine. Дедлайн: 15 листопада. Мета — щоб журі сказало «вау»:
кожна карта звучить по-своєму, звук чесно пояснюється даними, незрячий може досліджувати карту сам.
Працюй по етапах. Після кожного: тести в test.html, коміт, короткий звіт (що зроблено, що ні, чому).
Порядок: 9 → 10 → 11 → 12 → 13. Якщо час підтискає — спрощуй усередині етапу, але не пропускай 9 і 10.

Головний принцип: **тембр = тема, ноти = дані.** З першого звуку чути, ПРО ЩО карта;
мелодія, гармонія й ритм розповідають, ЩО В НІЙ ЗМІНЮЄТЬСЯ. Кожне музичне рішення має `why`.

---

## Етап 9. Тема візуалізації (topic) + голосове/текстове введення

1. **Тема ≠ вигляд.** `sceneType` лишається тільки для зчитування пікселів.
   Додай `topic` і `src/topics/topics.json`: `id`, назви uk/en, синоніми uk/en (БЕЗ російської),
   одиниці, «що означає більше», `soundProfile`, `preset`.
   Теми: `co2`, `temperature` (SST, повітря), `ocean-currents`, `ice` (лід, сніг), `fires`,
   `precipitation` (дощ), `storms` (грози, урагани, циклони), `vegetation` (NDVI, ліси),
   `nightlights`, `clouds`, `sea-level`, `ozone`, `aerosols` (пил, дим), `generic`.
   У `samples/catalog.json` пропиши `topic` для відео галереї.
2. **UI введення теми** під полем завантаження: поле «Що на цій карті?» + кнопка 🎤 + перемикач мови UA/EN.
   - Голос: Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`), `lang` = `uk-UA` | `en-US`.
     Немає підтримки → ховаємо мікрофон, лишаємо текст.
   - Зіставлення: нормалізація (регістр, розділові знаки, CO2/СО2/co₂/«це о два»), синоніми, частина слова,
     проста відстань Левенштейна; найкращий збіг + впевненість.
   - aria-live: «Розпізнано: вуглекислий газ CO₂. Enter — підтвердити, Esc — змінити».
     Нема збігу → список тем (з клавіатури). Тема з галереї підставляється сама, але її можна змінити.
3. **soundProfile теми** перекриває `INSTRUMENTS` і `KEY_ROOT` у composer.js / harmony.js
   (прибери прив'язку звучання до sceneType). Поля: `keyRule` (фіксована нота або правило з даних), лади,
   діапазон BPM, розмір (4/4, 3/4, 6/8, 5/4), інструменти для кожної партії, активні партії, ритмічний характер,
   простір (реверб/дилей), спецефекти теми. Мапінг: `topic` → `mapping/presets/<topic>.json`,
   успадковує пресет за sceneType.
4. **Звукові профілі (стартові, доопрацюй на слух):**

| Тема | Інструменти й текстури | Характер і зв'язок із даними |
|---|---|---|
| storms | саб-бас, гуркіт (шум + низькочастотний фільтр), литаври, низькі струнні тремоло, вітер | важкий низ; спалахи/викиди → удар грому (саб-бас + литавра), щільність хмар/опадів → тремоло й вітер, обертання циклону → панорама по колу |
| precipitation | арфа, піцикато, текстура дощу, педи | інтенсивність → щільність крапель/нот, хвилі наростання |
| co2 | низькі мідні, туба, дрон, кластери, орган | повільно; концентрація → щільність, дисонанс і регістр знизу вгору, тренд росту → повільне підвищення тону |
| temperature | струнні, фортепіано, валторна | значення за шкалою → висота й лад, аномалії → напруга |
| ocean-currents | арпеджіо фортепіано/арфи, хвилі, віолончель | швидкість течій → щільність арпеджіо, напрямок → панорама, вихори → кружляючі фігури |
| ice | челеста, скло, FM-дзвони, флажолети | рідко, 3/4; площа льоду → щільність, танення → тиша й спадання |
| fires | ударні, піцикато, тріск (шум), маримба | швидко; кожен спалах → акцент, площа → щільність |
| vegetation | кларнет, флейта, фагот, калімба | 6/8 пасторально; зеленість → мажорність, сезонний цикл → форма |
| nightlights | дзвіночки, челеста, ксилофон, дрон | кількість вогнів → щільність нот, кластери → акорди, нові вогні → нові ноти |
| clouds | педи, хор, повітряні текстури | плавно; хмарність → щільність педа |
| sea-level | віолончель, контрабас, хвилі | рівень → регістр, тренд → поступове «затоплення» басом |
| ozone | хор, скло, синтезований пед | діра → «провал» у спектрі (фільтр) |
| aerosols | гранулярні текстури, шум, флейта | концентрація → «зернистість» і каламутність звуку |
| generic | нейтральний оркестр | як зараз |

5. **Різноманіття з даних (усередині теми):** `seed` = хеш id/назви файлу (те саме відео = той самий трек);
   основна нота — квінтове коло за медіаною головної ознаки; BPM у діапазоні теми (загалом 50–140)
   за рухом; партії вступають за порогами даних, а не всі завжди; форма треку з тренду. Усе з `why`.
6. Тести: «викиди CO2», «вуглекислий газ», «carbon dioxide emissions» → co2; «гроза», «ураган»,
   «hurricane», «thunderstorm» → storms; одне відео з різними темами → різні тональність/інструменти/BPM;
   однаковий seed → однаковий трек.

## Етап 10. Область даних і стійкість до будь-якого вхідного файлу

1. Прохід A: `dataRegion` — зовнішній фон = темні або однотонні статичні пікселі, з'єднані з рамкою
   (заливка від країв). Збережи маску, bbox, `shape: disk|rect|other`; для диска — центр і радіус
   (найменші квадрати по межі).
2. Службові елементи: чорні смуги по краях, статичний текст/логотипи/дата (`overlayMask`), **шкала кольорів**
   (вузька статична смуга з монотонним градієнтом біля краю). Вирізай їх з аналізу. Зі шкали збережи
   опорні кольори → ознака `scaleValue` (колір → 0..1 за шкалою). Нема шкали → картка теми або hue як зараз
   (і чесно скажи в описі).
3. Зони 16×8, гарячі точки, changeScale, усі ознаки й нормалізація — ТІЛЬКИ в області даних.
   Для диска зони всередині кола, широта від центру (asin), підписи «північ/центр/південь диска».
   Для nightlights «темрява» — тільки всередині диска, космос не рахується.
4. Генератор синтетичних тестових відео й перевірки: глобус на чорному (1/3 кадру), плоска карта,
   карта + шкала + заголовок + логотип, чорні смуги, дуже темне, дуже світле, 3 с, 10 хв (проріджування),
   вертикальне, фото, графік. Критерії: IoU області ≥ 0.9, космос не в ознаках, шкалу знайдено й вирізано,
   усе грає без помилок у консолі.
5. **Картинки:** для `kind=image` — режим сканування: лінія йде по карті із заходу на схід
   (опція: з півночі на південь), колонки/смуги стають тактами, лінію видно на зображенні, 30–60 с.

## Етап 11. Бібліотека звуків (багато інструментів)

1. `src/audio/library/`: `registerInstrument({ id, family, kind: "sample"|"synth", range, tags, load })`.
   Ліниве завантаження — тема/стиль тягне тільки своє. Без інтернету — синтезаторний запасний варіант.
2. Семпли: решта tonejs-instruments (CC-BY 3.0; автор у README): cello, clarinet, bassoon, saxophone,
   trumpet, trombone, tuba, french-horn, organ, harmonium, guitar-acoustic/nylon/electric, bass-electric,
   xylophone тощо. Стисни (ogg/mp3, ноти через терцію).
3. Синтезатори на Web Audio: саб-бас, гуркіт/грім, FM-дзвони, скло, маримба, калімба, ханпан,
   формантний хор, теплий/холодний пед, дрон, гранулярна текстура, дощ, вітер, хвилі, тріск вогню.
4. Набори ударних: оркестровий (литаври, тарілки), ембієнт, електронний, «земний» (дерево, камінь, вода).
5. Стилі `src/styles/*.json`: orchestral, ambient, piano, electronic, choir — перекривають лише інструменти
   партій; мапінг і дані не змінюються. Перемикач стилю в UI + aria-live. За замовчуванням — профіль теми.
6. Тест: кожен інструмент звучить; трек кожної теми рендериться офлайн без помилок.

## Етап 12. Режим дослідження «дотик до карти»

1. Клавіша `E` або кнопка: зонд по карті — стрілки (Shift = більший крок), миша, дотик.
2. Звук зонда: висота = значення в точці (scaleValue або головна ознака), панорама = горизонталь,
   поза областю даних — тиша.
3. Озвучення (aria-live + за бажанням speechSynthesis uk/en): місце (широта/довгота для плоскої карти,
   частина диска для глобуса) і значення (з одиницями, якщо є шкала/картка).
4. `navigator.vibrate` на мобільних: сила = значення.
5. Тест: повний сценарій лише з клавіатури.

## Етап 13. Демо-готовність

1. Галерея: ≥ 4 справжні відео NASA різних тем (наприклад, ECCO2, нічні вогні, ураган, лід або CO2),
   для кожного — готовий `*.analysis.json`, картка (тема, змінна, одиниці, регіон, роки, опис, автори).
2. Короткий голосовий вступ перед треком (вимикається): «Температура океану, 2005–2007. Тепла вода —
   високі ноти…» = аудіолегенда для теми.
3. Деплой на GitHub Pages, перевір усе за живим посиланням (Chrome, Edge, Safari, телефон).
4. README: як працює (3 шари + тема + область даних), таблиця «звук ← дані», ліцензії й автори даних і семплів.
