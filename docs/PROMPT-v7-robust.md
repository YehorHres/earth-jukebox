# PROMPT v7 — стійкість до довільних відео користувача (без поломки галереї)

Проблема: на довільних відео NASA й інфографіках (приклад — висота лісу на глобусі, що обертається) звучання дивне.
Причини: (1) обертання глобуса чи рух камери сприймаються як «зміна даних» — звідси хибні події й гучність; (2) шкала не «синій→червоний» (зелені, viridis тощо), а програма
шукає «тепло» за відтінком; (3) невідомо, що означає «більше» (темніше чи світліше).

## 0. ГОЛОВНЕ ПРАВИЛО — НЕ ЗЛАМАТИ ГАЛЕРЕЮ
- Спершу створи «золотий» тест: для 5 відео галереї збережи хеш партитури (ноти, час, інструменти, BPM)
  поточного main у `tests/golden-scores.json`. Тест падає, якщо партитура галереї змінилась.
- Усі нові механізми вмикаються ЛИШЕ для відео без готової картки/аналізу (завантажені користувачем)
  або коли ознаки явно вказують на випадок нижче. Для відео галереї поведінка байт-в-байт та сама.
- Тести 15/A/16/17/v6 і золотий тест — зелені. Гілка `v7-robust`; зливати в main лише якщо все зелене.

## 1. Тип руху відео — визначити автоматично і читати кожен по-своєму (найважливіше)
Відео NASA/інфографіки бувають різні; один спосіб читання на всі не підходить. У проході A класифікуй
`motionType` (з поясненням і впевненістю; користувач може змінити в UI):
- **temporal** — карта/глобус на місці, змінюються самі дані (ECCO2, CO₂, лід, ураган). Як зараз.
- **rotating-globe** — глобус обертається (висота лісу, нічні вогні тощо). Обертання — це СКАНУВАННЯ
  простору, а не зміна даних: (а) не робити з обертання подій, гучності й «трендів»; (б) голос даних читає
  центральну смугу диска (меридіан, що зараз «перед слухачем»), панорама — схід/захід диска; (в) нова ділянка,
  що виходить з-за краю, — це не подія; (г) аудіоопис: «Глобус обертається: звучить те, що зараз у центрі».
  Визначення: зсув текстури всередині диска переважно горизонтальний і сталий (кореляція зсунутих кадрів).
- **camera-pan-zoom** — камера рухається над картою, що не змінюється → читаємо те, що в кадрі, рух камери
  не дає подій/гучності (механізм етапу 15 розширити).
- **static** — дані майже не змінюються і камера стоїть → режим сканування, як для картинок (захід → схід).
- **chart** — графік (осі, лінії, стовпці): сонифікація лінії — x = час треку, y = висота голосу даних;
  кілька ліній — різні тембри й панорама; перетини ліній — ерікон.
- **composite** — кілька панелей/карт поруч (порівняння «до/після», split-screen): знайти панелі;
  за замовчуванням читати найбільшу; для двох однакових панелей — режим порівняння (ліва панель — ліве вухо,
  права — праве).
У всіх типах: текст, логотипи, дати, шкали — поза аналізом (етап 15). Для `motionType` ≠ temporal
відключити ознаки, що реагують на рух (frameDiff, speed) як джерело гучності/подій.
Синтетичні тести на кожен тип (обертовий текстурований диск; панорама над статичною картою; графік із 2 лініями;
дві панелі поруч) + `field-tests`.

## 2. Шкала кольорів без легенди
- Якщо шкалу (colorbar) знайдено — як зараз, `scaleValue`.
- Якщо ні — визнач палітру кадру: кольори даних упорядкуй уздовж головної осі (світлота / PCA в Lab),
  отримай `paletteValue` 0..1. Для зелених/viridis/одноколірних шкал це працює краще за відтінок.
- Головна ознака для невідомих тем: `paletteValue` (замість warmth/hue), площа — частка «високих» значень.

## 3. Полярність «що означає більше»
- Перемикач у UI для завантажених відео: «Більше значення — це: [світліше] / [темніше] / [тепліше (червоне)]»,
  за замовчуванням — автоматично (світліше = більше; для шкал «синій→червоний» — червоне).
- Озвучення вибору; збереження разом із темою.
- Тема `vegetation`/«ліс», «висота лісу», «canopy height», «forest» → topic vegetation, polarity за перемикачем.

## 4. Автопідказки
- Тему пропонувати з назви файлу (словник тем), користувач підтверджує.
- Якщо впевненість низька — у описі чесно: «автоматичний режим: значення відносні».
