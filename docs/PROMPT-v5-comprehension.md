# PROMPT v5 — щоб незрячий РОЗУМІВ, що відбувається, а не чув набір звуків

Доповнює docs/PROMPT-v4.md (v4 = якість звуку, v5 = зрозумілість). Принцип «тембр = тема, ноти = дані»
лишається. Мета: людина без зору після 1–2 хвилин може відповісти: ЩО це за карта, ЩО змінюється,
КУДИ (росте/падає), ДЕ (захід/схід, яка зона), КОЛИ (який момент/дата) і НАСКІЛЬКИ (сильно/слабо).

Чому зараз не розуміють: (1) немає єдиної «граматики» — у кожній темі одне й те саме кодується
по-різному; (2) голос даних тоне в музиці; (3) немає точки відліку — не чути, «високо» відносно чого;
(4) події не названі; (5) одночасно звучить забагато партій; (6) немає способу спитати «що зараз?».

## Загальний порядок робіт (v4 + v5)
v4-14 (мікс) → v4-15 (рамки/камера) → **A** → v4-16 → v4-17 → **B** → **C** → **D** → **E** → v4-18 → v4-19.
Після кожного етапу: тести, коміт, короткий звіт. Обов'язково сьогодні: A, B, C. D, E — якщо встигаємо.

## Етап A. Єдина граматика звуку + голос даних на першому плані

1. **Граматика (однакова для ВСІХ тем, `src/grammar.js` + показ у UI й README):**
   | Що в даних | Як звучить завжди |
   |---|---|
   | значення головної величини (більше/менше за змістом теми) | висота голосу даних: більше → вище |
   | площа/охоплення | гучність і кількість голосів |
   | швидкість змін | густота ритму й темп (лише між фразами) |
   | аномалія, рекорд, невизначеність | напруга: дисонанс, тремоло, шорсткість |
   | дискретна подія (спалах, новий об'єкт, різкий стрибок) | ерікон (фіксований короткий звук-знак теми) |
   | положення по горизонталі (захід ↔ схід, ліво ↔ право диска) | панорама (ліве ↔ праве вухо) |
   | положення по вертикалі | НЕ кодуємо висотою (висота зайнята значенням) — повідомляємо голосом |
   | час відео | час треку (+ м'які «тіки» шкали часу, див. п.4) |
   Полярність «більше» береться з картки теми (`moreMeans`). Тест: синтетичне відео з монотонним
   ростом головної величини → висота голосу даних росте монотонно (Спірмен ρ ≥ 0.9); з падінням — падає.
2. **Голос даних (`dataVoice`)** — одна чітка партія, яка «говорить» головною величиною: окремий
   впізнаваний тембр теми, завжди на першому плані. Решта (гармонія, пади, ударні) — супровід:
   нижче за гучністю (−6…−10 дБ), звільнене місце в частотах під голос даних (EQ-виріз), акорди
   підлаштовуються під його регістр (не перекривають). Під час мовлення музика приглушується (ducking ≥ 10 дБ).
3. **Ліміт уваги:** одночасно на першому плані ≤ 3 потоки даних (голос даних + до 2 солістів зон).
   Солісти — різні тембри, розведені в панорамі; мінімальна відстань між зонами солістів ≥ 3 зони.
4. **Точка відліку:** (а) на початку треку 1–2 с звучить «референсний тон» — як звучить середнє/норма
   (або значення на першому кадрі); далі він тихо тримається як дрон-орієнтир, щоб відхилення були чутні;
   (б) «тіки» шкали часу — дуже тихий клік на кожну одиницю часу з картки (місяць/рік) або кожні 10 с,
   сильніший на кожен 4-й/12-й; вимикаються.
5. **Ерікони подій** — для кожної теми 2–4 фіксовані знаки (наприклад storms: «поштовх вітру», «блискавка»;
   ice: «тріск», «крапля»; nightlights: «іскра»; fires: «спалах»; co2: «порив»), однакові по всьому треку.
   Кожен ерікон є в легенді. Тест: ерікон звучить ≤ 100 мс від часу події; одна подія — один знак.

## Етап B. Голос, що пояснює: вступ, мітки подій, «Що зараз?»

1. **Вступ (вимикається, ≤ 20 с):** тема, що показано, звідки дані, період, «як слухати» коротко:
   «Голос даних — фортепіано. Вище — більше льоду. Тріск — лід ламається. Ліве вухо — захід».
   Одразу після — референсний тон (етап A.4).
2. **Голосові мітки подій (режим «Розповідь»):** на 3–7 найважливіших подіях — коротка фраза ≤ 6 слів
   з датою/часом і місцем: «Вересень: мінімум льоду», «Схід: спалах пожеж». Музика приглушується.
   Дати: з картки (`timeRange`) перерахунок час відео → дата; немає — «на 1:20».
3. **Клавіша «Що зараз?» (W, також кнопка):** пауза не обов'язкова; озвучує: час/дата, розділ, значення
   головної величини (одиниці, якщо є шкала/картка, інакше «73 % шкали відео»), тренд за останні ~10 с
   (росте/падає/стабільно), де найактивніше (місце), які партії грають. Коротко, до 2 речень.
4. **Підсумок після треку:** 2–4 речення: загальний тренд (на скільки змінилося від початку до кінця),
   мінімум і максимум (коли й де), кількість подій, «найважливіше». Також текстом у сторінці.
5. Озвучення: `speechSynthesis` (uk-UA / en-US за мовою інтерфейсу) АБО aria-live для скрінрідера —
   перемикач, щоб не було подвійного мовлення. Швидкість мови регулюється.
6. Шаблони тексту генеруються з аналізу (events, hotspots, тренди, діапазони), без вигаданих чисел;
   якщо одиниць немає — чесно «відносно цього відео».

## Етап C. Навчання на слух: інтерактивна легенда + огляд

1. **Інтерактивна легенда (до відтворення):** кнопки/клавіші 1–7: «так звучить мінімум», «максимум»,
   «ріст», «спад», «подія (кожен ерікон)», «захід/схід», «аномалія». Звуки генерує той самий рушій
   у тембрах поточної теми (не окремі записи). Кожна кнопка має текстовий опис.
2. **Огляд за 10 секунд:** стиснута версія всього треку — тільки голос даних + ерікони головних подій
   + референсний тон. Дає «загальну картину» перед детальним прослуховуванням.
3. Тест: легенда звучить для кожної теми; огляд триває 8–12 с; тренд огляду збігається з трендом даних.

## Етап D. Режими й навігація

1. Режими (перемикач, aria-live):
   - **Розповідь** — вступ + мітки подій + підсумок (за замовчуванням для нових користувачів);
   - **Музика** — без мовлення, повна оркестровка;
   - **Тільки дані** — голос даних + ерікони + референс, без супроводу (для перевірки і для журі:
     «ось чистий зв'язок звуку з даними»);
   - **Дослідження** — вже є (зонд по карті), додати озвучення значення в точці за граматикою.
2. Навігація клавішами: N/P — наступна/попередня подія; R — повторити останню фразу (4 такти);
   1–9 — соло партії; 0 — усі; [ ] — швидкість; W — «що зараз?»; ? — список клавіш (озвучується).
3. **Текстовий транскрипт** (аудіо-субтитри): список подій і розділів з часом/датою, місцем, поясненням;
   кожен пункт — посилання «перейти сюди»; синхронно підсвічується; доступний скрінрідеру.

## Етап E. Перевірка розуміння: вбудований слуховий тест

1. Сторінка `listening-test.html`: випадкові 10–20 с фрагменти треків галереї й синтетичних відео
   (без картинки). Питання з варіантами (клавіатура, скрінрідер): «росте чи падає?», «де більше —
   ліворуч чи праворуч?», «скільки подій?», «яка це тема?», «коли максимум — на початку, в середині,
   в кінці?». Правильні відповіді — з даних аналізу.
2. Результати зберігаються локально (IndexedDB), експорт CSV; підсумок: % правильних по кожному
   питанню й темі. Це цифри для пітчу («X % слухачів правильно визначили тренд без зору»).
3. Режим «до/після»: той самий тест на старій версії (тег git) і новій — щоб показати покращення.

## Критерії готовності (тести в test.html)
- Монотонність голосу даних (ρ ≥ 0.9) на синтетичних рядах; полярність за `moreMeans`.
- На першому плані ≤ 3 потоки; голос даних голосніший за супровід на ≥ 6 дБ (за audio-report).
- Ерікон ≤ 100 мс від події; кожен ерікон є в легенді; ducking під мовленням ≥ 10 дБ.
- «Що зараз?» відповідає ≤ 0.5 с, без вигаданих одиниць.
- Повний сценарій лише з клавіатури й скрінрідера: вибрати відео → легенда → огляд → розповідь →
  N/P по подіях → W → підсумок.
- Оновити README: розділ «Граматика звуку» (таблиця з етапу A) — це головний аргумент для журі:
  «вивчив раз — розумієш будь-яку карту».
