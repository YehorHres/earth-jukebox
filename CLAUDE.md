# Earth Jukebox — команда ANDD (NASA Space Apps Challenge 2026)

Дедлайн: 15 листопада 2026. Мова інтерфейсу й спілкування — українська, назви в коді — англійською.

## Челендж
"Earth Jukebox": перетворити візуалізації NASA Earth Information Center (EIC) на музику
(сонифікацію), щоб Earth science стала доступною для незрячих і слабозорих людей.
Звук має бути і науково чесним (кожен музичний елемент пояснюється даними кадру),
і живою, приємною музикою. Доступність — головна тема челенджу.

## Що будуємо
Вебджукбокс: користувач обирає візуалізацію NASA (галерея) або завантажує свою →
застосунок зчитує кадри відео/зображення → грає музику синхронно з картинкою.
Усе в браузері, без бекенду. Деплой — GitHub Pages.

## Архітектура (головний принцип: нічого не обмежуємо, все розширюється)
Три незалежні шари. Новий параметр чи інструмент додається, не переписуючи решту.

1. **Зчитування → «Аудіо-ДНК кадру».** Набір ознак-плагінів: кожна ознака — функція
   `кадр → число 0..1` (або карта по зонах). Нова ознака = нова функція в реєстрі.
   Плюс часові ознаки по вікнах 1 / 10 / 20 / 40 кадрів (швидкість, прискорення, тренд).
2. **Мапінг — таблиця (JSON), не код.** Як мод-матриця синтезатора: які ознаки з якими
   вагами й кривими керують якими музичними параметрами. Кілька ознак можуть керувати
   одним параметром (зважена сума). Таблицю показуємо в UI як пояснення для журі.
3. **Композитор — дані керують музичними рішеннями, а не окремими нотами:**
   гармонія (акордові прогресії, модуляції, дисонанс), партії (бас, педи, арпеджіо,
   мелодія фразами, контрмелодія, ударні, FX), справжні інструменти (семпли),
   «людське» виконання, форма треку (вступ → наростання → кульмінація → розв'язка).

Формат між шарами фіксований — змінюємо тільки разом:
- шар 1 віддає: `{ time, features: { name: value, ... }, zones: {...} }` для кожного кадру;
- шар 2 віддає: `{ musicalParam: value, ... }` для кожного такту;
- шар 3 читає тільки результат шару 2.

## Ознаки (backlog, від простих до складних)
- Легкі: тепловий індекс (hue), насиченість, яскравість, контраст, активна маса,
  частка суші/фону, вертикальний центр мас, баланс ліво/право, викиди > 3σ,
  різниця між кадрами, тренд.
- Середні: щільність контурів (Собель), ентропія, к-сть кольорових кластерів (K-Means),
  к-сть «плям» (зв'язні області).
- Складні (якщо буде час): 2D FFT, фрактальна розмірність, вихори, анізотропія.
- Окремий режим: графіки (похідні, перетини ліній, довірчі інтервали).
Банк ідей мапінгу — `docs/ideas-gemini.txt` (ідеї, не обов'язкова основа).

## Доступність (обов'язково для кожної фічі)
Керування з клавіатури, підписи й aria-live для скрінрідера, текстовий опис кожної
візуалізації, аудіолегенда («так звучить холодне / тепле»), mute/solo для партій.

## Поточний стан
`prototype/index.html` — v1, робочий прототип в одному файлі (Web Audio, 4 прості шари).
Використовуємо як довідку: зчитування кольору → значення, вікна 10/20/40, синхронізація
з відео, a11y. Нова версія будується за архітектурою вище.
`samples/` — тестові візуалізації (ecco2_sst_flow: течії й температура океану).

## Технічні правила
- Запуск тільки через локальний сервер (`npx serve` або `python -m http.server`),
  не file:// — інакше браузер не дасть читати пікселі відео.
- Відео класти і `.webm`, і `.mp4` (вбудований браузер Claude не грає MP4, Safari — WebM).
- Бібліотеки (Tone.js тощо) — через CDN, із запасним варіантом без інтернету.
- Кожна людина працює у своєму модулі/гілці; перед роботою `git pull`.
- Перед комітом: відео з `samples/` аналізується і грає без помилок у консолі.
